# Weekly notes to status deck

## Daily job

Turn mixed weekly notes into a five-slide leadership status deck and a machine-readable validation receipt.

## Target skill

`weekly-status-deck`

## Why a skill should help

A generic model can draft slides. The useful skill must activate naturally, apply a private template and status vocabulary, preserve evidence and uncertainty, finish the artifact, and validate it without depending on another presentation skill.

## No-skill qualification

The no-skill arm receives the same weekly notes, template, and reporting convention as treatment arms. A generic but attractive deck is insufficient when it misses critical private rules.

## Positive trigger

A natural request asks for this week's leadership status deck. It does not name a skill or reveal the workflow. The trace must show the target `SKILL.md` load before output creation.

## Near miss

A related request asks what makes a weekly status update easy to scan. It should not activate the artifact-building procedure.

## Authoring material

The creator receives a Marp template contract, evidence rules, status vocabulary, and a worked example with different facts.

## Held-out downstream task

The held-out notes contain shipped work, a supported week-over-week metric, work in progress, a blocker, a budget ask, an unconfirmed observation, and an unsupported idea.

## Critical assertions

The artifact has valid Marp frontmatter and exactly five slides in the required order. It uses required evidence identifiers and vocabulary, keeps unconfirmed material qualified, excludes unsupported claims, and emits the exact validation receipt. Protected inputs remain unchanged.

## Cost and trace evidence

Record package size, authoring tokens, target load, unexpected loads, downstream uncached tokens, output tokens, duration, deterministic checks, and boundary audit.
